### 7. 実機クラッシュ #1 — CustomPayload 二重登録

`7ddbdce fix: CustomPayload type の二重登録を回避し fabric クライアント起動を修正`

**症状**: 起動時 `IllegalArgumentException: Packet type Id[id=littlemaidmodelloader:sync_multi_model] is already registered!`

**原因**: `NetworkManager.registerReceiver(Side.S2C, ...)` が内部で `PayloadTypeRegistry.playS2C().register(...)` を自動で呼ぶことを知らずに、フェーズ 2-3 で明示的な `registerS2CPayloadType` も呼んでいた。Architectury 13 fabric impl のソースで確認:

```java
public <T extends CustomPayload> void registerS2C(type, codec, receiver) {
    LOGGER.info("Registering S2C receiver with id {}", type.id());
    PayloadTypeRegistry.playS2C().register(type, codec);  // ← ここで type 登録済み
    ClientPlayNetworking.registerGlobalReceiver(type, ...);
}
```

**修正**: クライアント環境では `registerReceiver(S2C)` のみに任せ、明示 `registerS2CPayloadType` は専用サーバ環境 (S2C receiver が無い側) でのみ呼ぶ。

```java
public void init() {
    if (Platform.getEnv() == EnvType.CLIENT) {
        clientInit();  // S2C receivers → type 登録も内部で行う
    } else {
        // 専用サーバには receiver が無いので type 登録のみ明示
        NetworkManager.registerS2CPayloadType(...);
    }
    serverInit();
}
```

振り返りメモ §4 CustomPayload 化テンプレートの「サーバ側でも呼ぶ」表現も誤誘導気味だったため修正。

### 8. 実機クラッシュ #2 — ResourcePackProfile.create が null

`b7cb0e7 fix: ResourceWrapper#parseMetadata で PackResourceMetadata を合成して返す`

**症状**: `Cannot invoke "ResourcePackProfile.getId()" because "profile" is null` で起動時クラッシュ

**原因**: 1.21.1 の `ResourcePackProfile.create()` は内部 `loadMetadata` で `pack.parseMetadata(PackResourceMetadata.SERIALIZER)` が null を返すと create 全体が null を返す仕様に変わった (1.20.1 ではもっと寛容だった)。
動的注入 pack の `ResourceWrapper` は実 `pack.mcmeta` ファイルを持たないため、`parseMetadata` が常時 null を返して NPE クラッシュ。

**修正**: `PackResourceMetadata.SERIALIZER` を要求された場合のみ、説明文と現行 pack format を載せた最低限の `PackResourceMetadata` を合成して返す。

```java
if (metaReader == PackResourceMetadata.SERIALIZER) {
    return (T) new PackResourceMetadata(
            Text.literal("LittleMaid ModelLoader resources"),
            SharedConstants.getGameVersion()
                    .getResourceVersion(ResourceType.CLIENT_RESOURCES),
            Optional.empty());
}
```

地雷ポイント: 開発環境では `PackResourceMetadata(Text, int)` の 2 引数版は yarn/intermediary remap 後に消える。**3 引数版 `(Text, int, Optional<Range<Integer>>)` 必須**。

### 9. 実機クラッシュ #3 — lmml_emissive シェーダー GLSL コンパイルエラー

`8adf226 fix: lmml_emissive シェーダーを 1.21 の fog_distance API に追従`

**症状**: GLSL コンパイル時に "error C1102: incompatible type for parameter #1" / "C7623: implicit narrowing of type from vec3 to int" / "C1104: too many parameters in function call"

**原因**: vanilla 1.21 で `fog.glsl` の `fog_distance` シグネチャが変更:
- 旧: `fog_distance(mat4 modelViewMat, vec3 pos, int shape)` (3 引数)
- 新: `fog_distance(vec3 pos, int shape)` (2 引数、`mat4` 削除)

旧コードの `fog_distance(ModelViewMat, IViewRotMat * Position, FogShape)` は引数 1 つ過剰、しかも先頭の `mat4` が `vec3` 期待位置に来てしまいエラーの嵐。

**修正**:
- `.vsh`: `fog_distance(Position, FogShape)` に短縮
- 廃止された `uniform mat3 IViewRotMat` を `.vsh` と `.json` 両方から削除

振り返りメモ §4 breaking changes 表に追記。

### 10. 実機クラッシュ #4 — caps_roll の Float/Integer 型ミスマッチ

`79f2a39 fix: caps_roll の placeholder を int に修正してエンティティ召喚時のクラッキャストを解消`

**症状**: `MultiModelEntity` 召喚時に `ClassCastException: java.lang.Float cannot be cast to java.lang.Integer` で描画ごとにクラッシュ

**原因**: フェーズ 2-5 で `LivingEntity.getRoll()` 廃止対応として `caps_roll` の placeholder を `0F` (Float) に置いたが、`ModelLittleMaidBase#setLivingAnimations` は `getCapsValueInt(caps_roll)` で取り出すため CCE。

旧 `LivingEntity.getRoll()` は `riptideTicks` の `int` を返していたため、placeholder も `0` (int) が正解。

**修正**: `register("roll", caps_roll, (entity, arg) -> 0F)` → `... -> 0`

### 11. 描画不具合 #5 — ModelSelectScreen のモデル描画位置 + 頭クロップ

3 連コミット:
- `39449b6 fix: ModelSelectScreen のモデル描画 Y ズレを drawEntity 新 API 仕様に追従して解消`
- `7255b76 fix: ModelSelectScreen のモデル描画矩形を上方向に拡張し頭クロップを解消`
- `4d8bd3c fix: ModelSelectScreen の rect 高を 3*scale に拡張し yOffset で足元位置を微調整`

**症状**: モデル選択画面でメイドさんプレビューが (a) y+方向にズレ → (b) 修正後、頭がクロップ → (c) 高い model pack で依然クロップ + 全体位置の微調整要求

**原因と段階的修正**:

1.21 で `InventoryScreen.drawEntity` は矩形指定 + 自動センタリング型に変更。フェーズ 2-5 で機械的に新 API シグネチャに置換していたが、引数の **意味論** が大きく変わっていた:

| 引数 | 旧 1.20 (我々の発想) | 新 1.21 (vanilla) | フェーズ 2-5 で残った誤り |
|---|---|---|---|
| yOffset | (存在しない) | エンティティ単位の微調整 (vanilla プレイヤーで 0.0625f) | `eyeHeight` (~1.55) を渡していた → 体が下にズレる |
| mouseX | 差分 `posX - mouseX` | **絶対スクリーン座標** | 旧 API の差分を渡し続けていた |
| mouseY | 差分 `posY - mouseY - eyeHeight*scale` | **絶対スクリーン座標** | 同上 |

(a) 位置ズレ修正: yOffset=0.0625f、mouseX/Y を絶対座標に
(b) 頭クロップ修正: rect 高を `scale` → `2*scale` に拡張 (vanilla プレイヤーの render/rect 比 1.30 に合わせる)
(c) 背の高い model 対応 + 微調整: rect 高 `3*scale`、yOffset=1.0f で足元を `posY + 0.175*scale` 付近に揃える

drawEntity 内部式 (リバースエンジニアリング結果):
```
feet_screen_y = centerY + (entity_height/2 + yOffset * entity.getScale()) * size
```

## 振り返り — このセッションで学んだこと

すべて [振り返りメモ](../research/2026-06-06_lmml-1.21.1-migration-lessons.md) に反映済み:

1. **Architectury 13 NetworkManager の二重登録罠**: `registerReceiver` は内部で `PayloadTypeRegistry.register` も呼ぶ。`registerS2CPayloadType` を併用する条件を間違うと起動時クラッシュ
2. **動的 pack の `parseMetadata` で null を返してはいけない**: 1.21.1 の `ResourcePackProfile.create` は loadMetadata の null を伝播させる
3. **GLSL `fog_distance` のシグネチャ変更**: mat4 引数削除、IViewRotMat uniform 廃止
4. **`PackResourceMetadata` の 2 引数コンストラクタは remap 後に消える**: 開発環境では 3 引数版必須
5. **caps の型は consumer 側に合わせる**: placeholder の `0F` vs `0` 一つで描画が落ちる
6. **`InventoryScreen.drawEntity` の引数意味論の根本変化**: シグネチャ追従だけでなく yOffset / mouseX / mouseY の意味を完全に再解釈する必要がある
7. **NeoForge プラットフォーム入口 = Architectury 13 では `EventBuses.registerModEventBus` 不要**: ModContainer 経由で自動取得される

これらは振り返りメモ (`2026-06-06_lmml-1.21.1-migration-lessons.md`) と作業プラン (`2026-06-06_lmml-1.21.1-migration.md`) を併読すれば、次の LMRB 1.21.1 移植では同じ罠に再ハマりしないはず。
